cdp

The Customer Data Platform (CDP) module for the Salesforce Marketing Cloud SDK.

Overview

The CDP module enables integration with Salesforce Marketing Cloud's Customer Data Platform, allowing you to:

  • Track user engagement and profile events

  • Manage user consent (opt-in / opt-out)

  • Attach location context to events

  • Manage session state

Integration

1. Add Dependencies

Add the SFMC SDK and CDP module to your app's build.gradle:

dependencies {
    implementation 'com.salesforce.marketingcloud:sfmcsdk:3.0.+'
    implementation 'com.salesforce.marketingcloud:cdp:3.0.1'
}

2. Initialize the SDK

Initialize the SDK in your Application class:

class MyApplication : Application() {
    override fun onCreate() {
        super.onCreate()

        SFMCSdk.configure(this, SFMCSdkModuleConfig.build {
            cdpModuleConfig = CdpConfig.Builder(
                    this@MyApplication,
                    "your-cdp-app-id",       // UUID format
                    "https://your-endpoint.salesforce.com"
                )
                .trackScreens(true)          // optional, default: false
                .trackLifecycle(true)        // optional, default: false
                .sessionTimeout(600L)        // optional, default: 600 seconds
                .build()
        }) { status ->
            if (status.status == InitializationStatus.SUCCESS) {
                CdpSdk.requestSdk { sdk ->
                    sdk.consent = Consent.OPT_IN
                }
            }
        }
    }
}

3. Track Events

CdpSdk.requestSdk { sdk ->

    // Engagement event
    sdk.track(Event.engagement("add_to_cart", mapOf(
        "product_id" to "SKU-123",
        "price" to 9.99
    )))

    // Profile event
    sdk.track(Event.profile("contactPointEmail", mapOf(
        "email" to "user@example.com"
    )))
}

4. Manage Consent

CdpSdk.requestSdk { sdk ->
    sdk.consent = Consent.OPT_IN   // start tracking
    sdk.consent = Consent.OPT_OUT  // stop tracking and clear queued events
    // Note: Consent.PENDING cannot be set manually
}

5. Set Location

Provide location context that will be attached to outgoing events until it expires:

CdpSdk.requestSdk { sdk ->
    sdk.setLocation(Coordinates(37.7749, -122.4194), expiresIn = 3600L) // expires in 1 hour
    sdk.setLocation(null, expiresIn = 0L) // clear location
}

Configuration Options

endpointStringrequiredTenant-specific HTTPS endpoint URL
trackScreensBooleanfalseAutomatically track screen views
trackLifecycleBooleanfalseAutomatically track app launch / backgrounded events
sessionTimeoutLong600Session timeout in seconds
eventFlushRateEventFlushRateQuantity(20)Controls when queued events are sent

Event Flush Rate

// Flush after accumulating 20 events (default)
.eventFlushRate(CdpConfig.EventFlushRate.Quantity(20))

// Flush after 20 events OR every 30 seconds, whichever comes first
.eventFlushRate(CdpConfig.EventFlushRate.QuantityAndInterval(20, 30_000L))

Features

Event Tracking

  • Track engagement events (user interactions and behaviors)

  • Track profile events (identity, email, phone, address)

  • Automatic screen view and lifecycle events when enabled in config

  • Reserved event names (appFirstLaunch, appLaunch, appUpdate, screenView) are managed by the SDK

Consent Management

  • Opt-in / opt-out states, persisted across sessions

  • Queued events are not sent until consent is OPT_IN

  • OPT_OUT clears any pending queued events

Location

  • Manually attach coordinates to outgoing events with a configurable expiry time

  • Location is cleared automatically when it expires or when consent is OPT_OUT

Session Management

  • Sessions are tracked automatically based on app foreground/background transitions

  • Configurable session timeout (default: 10 minutes)

Troubleshooting

  1. SDK does not initialize

    • Verify appId is a valid UUID

    • Verify endpoint is a valid HTTPS URL

    • Check logcat for detailed error messages (CdpSdk tag)

  2. Events are not being sent

    • Verify consent is set to Consent.OPT_IN

    • Check that the event flush threshold has been reached, or use QuantityAndInterval to also flush on a timer

    • Review logcat (EventManager tag)

  3. Location not attached to events

    • Confirm setLocation was called before the events were tracked

    • Check that the expiry has not elapsed
