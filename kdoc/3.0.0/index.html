cdp

The Customer Data Platform (CDP) module for the Salesforce Marketing Cloud SDK.

Overview

The CDP module enables integration with Salesforce Marketing Cloud's Customer Data Platform, allowing you to:

  • Track user events and behaviors

  • Manage user profiles and attributes

  • Integrate with other Marketing Cloud services

  • Handle user consent management

  • Track location data

  • Manage session state

Integration

1. Add Dependencies

Add the SFMC SDK and CDP module to your app's build.gradle:

dependencies {
    implementation 'com.salesforce.marketingcloud:sfmcsdk:1.0.6'
    implementation 'com.salesforce.marketingcloud:cdp:${version}'
}

2. Initialize the SDK

Initialize the SDK in your Application class:

class MyApplication : Application() {
    override fun onCreate() {
        super.onCreate()
        
        // Configure the SFMC SDK with CDP module
        SFMCSdk.configure(this, SFMCSdkModuleConfig.build {
            // Configure CDP module
            cdpModuleConfig = CdpConfig.Builder(this, "your-cdp-app-id", "your-cdp-endpoint")
                .trackScreens(true)  // Enable screen tracking (default: false)
                .trackLifecycle(true)  // Enable lifecycle tracking (default: false)
                .sessionTimeout(600L)  // Set session timeout in seconds (default: 600)
                .build()
            
            // Configure other modules as needed
            // pushModuleConfig = ...
        }) { status ->
            // Handle initialization status
            when (status.status) {
                InitializationStatus.SUCCESS -> {
                    // SDK initialized successfully
                    CdpSdk.requestSdk { sdk ->
                        // Set initial consent state if needed
                        sdk.consent = Consent.OPT_IN
                    }
                }
                InitializationStatus.FAILURE -> {
                    // Handle initialization failure
                }
            }
        }
        
        // Optional: Request SDK state
        SFMCSdk.requestSdk { sdk ->
            Log.d("MyApp", "SDK State: ${sdk.getSdkState()}")
        }
    }
}

3. Request the CDP SDK Instance

To use CDP features in your activities or fragments:

class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        // Request the CDP SDK instance
        CdpSdk.requestSdk { sdk ->
            // Track an event
            sdk.track(Event.engagement("button_click", mapOf(
                "button_id" to "login",
                "screen" to "main"
            )))
            
            // Set user consent
            sdk.consent = Consent.OPT_IN
            
            // Set location
            sdk.setLocation(Coordinates(37.7749, -122.4194), 3600L) // 1 hour expiration
        }
    }
}

Configuration Options

appIdStringRequired. Your CDP Application ID in UUID format.
endpointStringRequired. The endpoint URL for sending events.
trackScreensBooleanOptional. Enable automatic screen tracking. Default: false
trackLifecycleBooleanOptional. Enable automatic lifecycle tracking. Default: false
sessionTimeoutInSecondsLongOptional. Session timeout duration in seconds. Default: 600

Features

Event Tracking

  • Track user interactions and behaviors

  • Support for engagement, profile, and consent events

  • Automatic validation of event types and attributes

  • Built-in support for screen views and lifecycle events

Consent Management

  • Track user consent preferences

  • Support for opt-in and opt-out states

  • Automatic consent state persistence

  • Integration with privacy regulations

Location Tracking

  • Track user location with expiration

  • Automatic location updates

  • Geofencing support

  • Location-based event triggering

Session Management

  • Automatic session tracking

  • Configurable session timeout

  • Session state persistence

  • Session-based event correlation

Best Practices

  1. Initialization

    • Initialize the SDK as early as possible in your Application class

    • Always provide valid configuration values

    • Handle initialization errors appropriately

    • Set up logging before initialization for debugging

  2. Event Tracking

    • Use meaningful event names

    • Include relevant attributes

    • Avoid using reserved event types

    • Validate event data before sending

  3. Consent Management

    • Always respect user consent choices

    • Update consent state when user preferences change

    • Never set consent to PENDING manually

    • Handle consent changes appropriately

  4. Location Tracking

    • Set appropriate expiration times

    • Consider battery impact

    • Handle location permission changes

    • Validate coordinates before sending

Troubleshooting

Common issues and solutions:

  1. SDK Initialization Fails

    • Verify your configuration values

    • Check network connectivity

    • Ensure proper permissions are set

    • Review logcat for detailed error messages

  2. Events Not Being Tracked

    • Verify consent state

    • Check event validation

    • Ensure proper SDK initialization

    • Review event manager logs

  3. Location Updates Not Working

    • Verify location permissions

    • Check location services status

    • Ensure proper coordinate format

    • Review location manager logs
